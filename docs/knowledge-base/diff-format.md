# Diff format notes

Implementation: `src/core/diff.ts`. Tests: `test/core/diff.test.ts`. Fixtures: `test/fixtures/*.diff`.

## Anatomy of what git prints

```
diff --git a/src/auth/session.ts b/src/auth/session.ts      <- section header (one per file)
index f7bd5c5..c93f636 100644                               <- extended header lines
--- a/src/auth/session.ts
+++ b/src/auth/session.ts
@@ -10,7 +10,7 @@ export interface Session {                   <- hunk header: -oldStart,oldCount +newStart,newCount
 context line                                               <- first character is the line's role:
-removed line                                                   ' ' context, '-' removed, '+' added,
+added line                                                     '\' "No newline at end of file"
\ No newline at end of file
```

Hunk counts are why redaction must keep every line: change the line count and `@@ -a,b +c,d @@` lies.

## Quirks captured from real output (and how the parser handles each)

| Quirk | Seen in fixture | Handling |
| --- | --- | --- |
| New file: `new file mode`, `--- /dev/null` | `new-file` | status `added`; old path taken from the `+++` line |
| Deleted file: `deleted file mode`, `+++ /dev/null` | `deleted-file` | status `deleted`; `path` is the old path |
| Rename: `similarity index N%`, `rename from/to`, maybe no hunks at all | `renamed-file` | status `renamed`; paths from the rename lines (authoritative) |
| Mode change only: `old mode` / `new mode`, no hunks | `mode-change` | `modeChangeOnly = true` |
| Binary: `Binary files a/x and b/x differ` (or `/dev/null` for adds) | `binary-file` | `binary = true`; content never sent |
| `GIT binary patch` (with `--binary`) | inline test | `binary = true` |
| **Trailing TAB after the path on `---`/`+++` when the path contains a space** | `special-paths` | strip from the first TAB |
| Non-ASCII or special paths are double-quoted with octal UTF-8 escapes (`"docs/r\303\251sum\303\251.md"`) | `special-paths` | `unquoteGitPath` decodes bytes as UTF-8, by code point (an emoji is two UTF-16 units and must not be split) |
| Paths with spaces make `diff --git a/x y b/x y` ambiguous | `special-paths` | try each ` b/` split and prefer the one where both halves are equal; `---`/`+++` and rename lines override |
| CRLF content: lines end in `\r` | `crlf-edit` | text is preserved byte for byte; headers are matched after stripping a trailing `\r` |
| Combined (merge) diffs: `diff --cc`, `@@@`, two prefix columns | inline test | two columns are inspected when counting additions/deletions |
| Text before the first `diff --git` | none | ignored |
| A diff cut off mid-file | inline test | parsed as far as it goes; never throws |

Submodule changes: `--submodule=short` forces the plain `Subproject commit <sha>` form, which parses as a normal
modified file (with `diff.submodule=log` git prints `Submodule ...` lines that would attach to the previous file).
Not specially handled (best effort): symlinks (a one-line diff), non-UTF-8 content.

## Skip rules

A file's content is replaced by its name when it is **sensitive** (`isSensitivePath`, checked on both old and
new path), **binary**, or a **lock file** (`isLockFile`: `package-lock.json`, `npm-shrinkwrap.json`,
`pnpm-lock.yaml`, `bun.lockb`, `go.sum`, `packages.lock.json`, `gradle.lockfile`, `.terraform.lock.hcl`,
`Package.resolved`, and anything ending in `.lock`). Names are matched on the lower-cased base name, with
Windows separators normalised.

## Truncation

When the redacted text of all included files exceeds the budget (`maxChars`; 40,000 for commits, 60,000 for PRs):

1. If there are more files than `budget / 400`, keep the files with the most changed lines and **omit** the
   rest (listed by name).
2. Give each remaining file `min(its size, fair share)`: small files stay whole, big files absorb the cut
   (water-filling).
3. Cut each over-budget file at a line boundary, keep its header, and append
   `[... N more lines truncated by CommitCraft ...]`. A single enormous line (minified code) is hard-cut.
4. The rendered prompt says the diff was too large and tells the model to describe only what is shown, and the
   user gets a notice.
5. The "Changed files" overview is capped at 100 lines and the "not included" list at 50, each path at 200
   characters, with an "... and N more files" line, so the prompt stays bounded however many files the diff touches
   (without the caps, 20,000 files produced a 3 MB prompt for a 40 KB budget). The totals still count every file.
6. A giant single content line (minified code) is dropped whole: the file keeps its header and the marker.

## Fixtures

Generated by `scripts/make-fixtures.sh`, which builds a throwaway repository and captures real
`git diff --cached` output for: `normal-edit`, `new-file`, `deleted-file`, `renamed-file`, `binary-file`,
`lock-file`, `mode-change`, `special-paths`, `crlf-edit`, `mixed-commit`, `secrets`, `empty`. A huge diff is
generated in code (`makeHugeDiff`). `secrets.diff` holds `{{FAKE_...}}` placeholders that
`test/helpers/fakeSecrets.ts` fills at test time, so no secret-shaped string lives in the repository.
`.gitattributes` marks the fixtures `-text` so a Windows checkout cannot rewrite their line endings.
